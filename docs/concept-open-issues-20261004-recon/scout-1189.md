# Scout report: upstream #1189 (LoRa remote management), tree fork-dev a9e64cf6, read-only

BLUF: HMAC-SHA256 exists only as ESP32/mbedtls code, duplicated in 3 places, TCP challenge-response only; nothing runs on nRF52 and nothing authenticates a LoRa frame. Own-call DMs are parsed in OnRxDone with a clean hook point and a reply helper (SendPong pattern), but commandAction is not reentrant/RX-safe and must run from loop context.

4.4 Max text on air: sendMessage hard limit 160 chars for `{dst}text` (docs/architecture/11-wire-format.md:797); on-air frame <= UDP_TX_BUF_SIZE 255 B (configuration_global.h:272) incl. 6 B header, source path, dest path/call, `{NNN`; payload buffer MC_PAYLOAD_LEN 256 (aprs_structures.h:56). ### 7. Risks

7.1 Replay: frame is public and relayed by every node (max_hop), echoed by server/gateways (extUDP/KISS taps at lora_functions.cpp:1530-1545 see it too) and possibly held by store nodes for hours (2.6). Existing dedup is NOT a replay defence: msg_id ring 60 entries (rolls in minutes on a busy channel), dmDedup 16 slots/1 h, both keyed on attacker-changeable fields (msg_id is outside the payload; an attacker can resend the same payload with a fresh msg_id; NNN reuse hits dmDedup only for 1 h). So the tag must bind (command, sender call, destination call, freshness) and the node must keep its own replay state (last accepted counter/timestamp, persisted or conservative after reboot: a persisted high-water mark like src/msgid_counter.h's scheme avoids a flash write per frame).
7.2 Dedup dropping a repeated identical command: legitimate repeat (toggle on, off, on) with identical text+NNN inside 1 h is DUP at dmDedupCheck; a counter/timestamp field inside the plaintext makes each command unique -> not dropped. Also the radio retry ladder re-sends with fresh msg_id but same NNN: the command layer must be idempotent per counter (second copy rejected as replay yet still ACKed at link level; reply once).
7.3 Truncation: 160 chars at sendMessage, `{`->`(` escaping, %-decode (a `%` sequence in text is rewritten), control chars/non-ASCII filtered (charset_filter), payload cut by relays? (not cut, but dropped if >255 B). HMAC must be over the canonical command string as received, with fixed-width fields; reject on length mismatch; do not use `{` `%` in tag/command alphabet. Tag in hex or Base32/62 to survive the charset filter.
7.4 nRF52: no mbedtls; options = nRFCrypto_Hmac (CC310, needs nRFCrypto.begin/end, mutex-ish, avoid in 1 KB timer task, avoid concurrent use with BLE pairing hash_pin) or a ~120-line portable SHA-256/HMAC in a Arduino-free header (also gives host unit tests and removes the 3x duplication; needs Wycheproof/RFC 4231 vectors). nano printf: no %lld/%llu (memory nrf52-nano-printf-no-long-long): print counters/timestamps with %lu/%u only; hex-encode tags by hand, not printf("%02x") on uint64.
7.5 Visibility: command and tag are public by law/design. The tag must be a truncated HMAC (>=64 bit) over (dst call | src call | counter/ts | command) with the key never on air; HMAC-SHA256 output leaks nothing about the key; do not echo the key or expected tag in any reply/NACK/log; constant-time compare (ct_equal pattern net_console.cpp, kiss_functions.cpp:480); rate-limit failures (ADR idea 3/90 s) and do not reply to bad tags at all (a NACK is an amplifier/oracle and a DM storm; at most a silent counter + [REM] serial marker).
7.6 Spoofed source: msg_source_call is attacker-controlled; same-base-call check alone is NOT authentication. Same key on both nodes (or per-pair derived key) is required; the "other SSID of the same owner" relation is only a policy hint.
7.7 Both nodes of a pair must share the key, and the commanding side needs a sender: McApp/BLE can send plain text DMs; host tool (python, hmac stdlib, mirrors tools/hmac_connect.py) can generate the line. Without a sender tool the feature is unusable from a phone.
7.8 Server/gateway ingress (udp_frame_*.cpp) means an internet DM to the node would reach the hook if wired there; decide whether remote commands are accepted over the gateway path (probably NO: LoRa-only, or additionally require !msg_server).
