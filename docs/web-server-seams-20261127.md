# Production web server: seams, defects, parser design (analysis, 2026-11-27)

Scope: the production HTTP server (own server on `WiFiServer` / `EthernetServer`, `src/web_functions/`), not Safeboot.
Goal of FORMAL-02 wave 4: deterministic, provable request parsing, no duplicates, modular, behaviour identical unless
listed in section 7.2. Analysis only, no code changed. Tree: `fork-dev` @ f4f541d5 plus uncommitted edits (none in
`src/web_functions/`, none in `src/url_decode.*`). Pattern followed: `docs/udp-consolidation-20261127.md`.

Evidence rules: every claim carries file:line read in this tree. "not verified" marks what was not read or run. No build,
test, solver or bench run was made. `web_functions.cpp` below is `src/web_functions/web_functions.cpp` (5,274 lines);
other files are named in full or with their directory.

## 0. Result in eight lines

- The request path is `work_webpage` (:1039-1542, 504 lines): a byte loop into two `String`s, a guard call, 39 route
  branches (25 `indexOf` over the whole header, 14 `startsWith`), and handlers that re-parse `web_header` with
  `substring(indexOf(..)+n)` and no `-1` check.
- 14 defects verified (section 2). Worst: the spectrum page sweeps the radio inside the handler (>= 4 s, no LoRa RX,
  leaks about 6 kB per view); `setparam` without `=` uses the whole string as the value; an `HTTP/1.0` or version-less
  request line makes `setparam`, `call_function`, `getparam` and `send_message` swallow the rest of the header.
- Nothing found that corrupts memory: every buffer write is bounded (`web_header`/`web_currentLine` at 1023, body
  readers at their caps). The defects are wrong route, wrong value, heap churn and long blocking.
- Duplicates (section 3): three percent decoders (one dead), nine hex-digit decoders, two body readers, seven
  hand-built response heads, two hardware RNG fills, 17 `send_http_header` + `sub_page_*` pairs.
- Already pure and tested, to keep: `web_guard.h` (1187-line test), `web_rm_parse.h` (693), `web_txbuf`, `web_auth`,
  `url_decode` (with a bounded proof, `specs/cbmc/url_decode`). Not covered by any host test: `work_webpage`, the four
  REST handlers, `web_setup.cpp`, `web_rm_handlers.cpp`.
- Design (section 6): six small pure units (`hex_digit.h`, `url_decode` with policy, `web_request.h`, `web_route.h`,
  `web_query.h`, `web_body.h`) plus `num_parse.h`; routes match on the request-line target only.
- Migration (section 7): 12 steps (0-11) in 3 waves; steps 0-3, 7 and 8 keep behaviour byte-identical for the corpus; the 10
  deliberate changes are in 7.2 for the operator.
- Net effect: `web_functions.cpp` 5,274 -> about 3,950 lines; new modules about 2,200 lines (850 of them moved code);
  net production about +750 lines; tests about +4,100 lines plus about 1,000 corpus lines.

### 6.2 Request head: `web_request.h`

Limits (explicit, all `#define`, no hidden `String`): `WEB_HEAD_MAX 1023` (= `WEB_HEADER_MAX` :1050 =
`WEB_GUARD_HEADER_MAX` `web_guard.h:79`), `WEB_COOKIE_MAX 255` (:1067), `WEB_CL_MAX 65535` (a body cap far above
`CONFIG_JSON_MAX` 6144, so the parse can say "absent / malformed / plausible" and the reader applies its own cap).

```cpp
struct WebSpan { const char *p; uint16_t n; };                                         // never owns, never NUL terminated
enum WebMethod : uint8_t { WM_NONE = 0, WM_GET, WM_POST, WM_HEAD, WM_OPTIONS, WM_OTHER };
enum WebHeadRes : uint8_t { WH_MORE = 0, WH_DONE, WH_LINE_TOO_BIG };
enum WebParseRes : uint8_t { WRQ_OK = 0, WRQ_BAD_REQUEST_LINE, WRQ_BAD_VERSION, WRQ_BAD_CONTENT_LENGTH };
struct WebHeadAcc { char head[WEB_HEAD_MAX+1]; char line[WEB_HEAD_MAX+1]; char cookie[WEB_COOKIE_MAX+1]; uint16_t head_len, line_len, cookie_len; int32_t content_length; uint8_t flags; };   // about 2.4 kB, allocated once at server start (heap), never on the stack
void webHeadInit(WebHeadAcc *a);                                                        // resets for the next connection, wipes cookie and line
WebHeadRes webHeadPush(WebHeadAcc *a, char c);                                          // one byte: window (<= 1023, rest dropped, `cut` set), line (<= 1023), Content-Length and `mcs=` captured per finished line
struct WebReq {
    uint8_t method, minor;                                                              // minor: 0 or 1 (HTTP/1.x); anything else WRQ_BAD_VERSION
    WebSpan target, path, query;                                                        // target = request-line target; path up to '?'; query after '?' (no '?')
    WebSpan host, origin;                                                               // first value, trimmed; counts below
    uint8_t host_n, origin_n, xmc_n, xmc_bad, sf_site, sf_dest, folded;                 // what web_guard.h needs, so the guard can stop re-scanning text
    int32_t content_length;                                                             // -1 absent
    bool cut;                                                                           // window was cut at WEB_HEAD_MAX
};
WebParseRes webReqParse(const char *buf, size_t len, bool cut, WebReq *out);            // pure; every span points into [buf, buf+len)
WebSpan webHeadCookie(const WebHeadAcc *a);                                             // the captured `mcs=` pair, from the full stream
int32_t webHeadContentLength(const WebHeadAcc *a);                                      // -1 absent
bool webHeadBadContentLength(const WebHeadAcc *a);                                      // malformed, over-large or a second differing value: the caller answers 400 (B6)
```

Rules (each one is today's behaviour unless marked B in 7.2):

- Request line: `METHOD SP target SP HTTP/1.x`; the version is the text after the last space (same split as
  `web_guard.h:602-623`). No version, or not `HTTP/1.0|1.1`: `WRQ_BAD_VERSION` (today: wrong values, D3; B3).
- `path` is `target` up to the first `?`; `query` the rest. Nothing after the request line is ever used for routing.
- Content-Length: digits only after trimming, value <= `WEB_CL_MAX`, first one wins, a second different one is
  `WRQ_BAD_CONTENT_LENGTH` (B6).
- `web_header` window bytes are identical to today's (the guard keeps judging the same 1023 bytes).
- Cookie: same rule as :1486-1507 (first `mcs=` after `:`, space or `;`), copied into `cookie[256]`.
- The head accumulator replaces `web_header` (heap `String`, 1 kB reserved once, :1051), `web_currentLine` (`String`),
  `web_cookie[256]` (stack) and the per-line `hdr_name` copy (:1480). Persistent heap goes from 1 kB to about 2.4 kB
  once; per-request heap churn goes to zero.

### 6.3 Route table: `web_route.h`

```cpp
enum WebRoute : uint8_t { WR_NONE = 0, WR_SCAFFOLD, WR_ASSET_CSS, WR_ASSET_JS, WR_ASSET_RMJS, WR_ASSET_AUJS, WR_LOGIN_NONCE, WR_LOGIN, WR_LOGOUT,
                          WR_LEGACY_PW, WR_RM_SEND, WR_RM_STATUS, WR_RM_PASSWD, WR_WEB_PASSWD, WR_RM_NODES_GET, WR_RM_NODES_POST, WR_RM_HEARD,
                          WR_PIN_STATUS, WR_PIN_ASSIGN, WR_GPIO_STATUS, WR_AU_STATUS, WR_SCREEN_RGB565, WR_SCREEN_OLED, WR_CALLFUNCTION,
                          WR_SENDMESSAGE, WR_GETMESSAGES, WR_SETPARAM, WR_GETPARAM, WR_CONFIG_GET, WR_CONFIG_POST, WR_PAGE_BASE /* + one per page */, WR_COUNT };
enum : uint8_t { WRF_PAGE = 1, WRF_NO_AUTH = 2, WRF_BODY = 4, WRF_STATE = 8 };           // PAGE: dispatcher sends 200 TEXT head; NO_AUTH: before the auth gate; BODY: needs Content-Length; STATE: mirrors webGuardIsStateChanging
struct WebRouteDef { const char *path; const char *key; const char *val; uint8_t methods; uint8_t route; uint8_t flags; };   // key/val: first query pair, NULL = ignore query
uint8_t webRouteMatch(uint8_t method, WebSpan path, WebSpan query);                      // returns WebRoute; WR_SCAFFOLD for "/" with no key, WR_NONE for anything else
```

Match rule, the only one: `path` equals a table path exactly (byte compare, case-sensitive); for path `/` the first
query pair is the selector (`page=<name>` exact name, `sendmessage`, `getmessages`, `loginnonce`, `login=`, `logout`,
`nodepassword`); method must be in the row's mask. No other byte is read. The table is a `static const` array of about
60 rows; the 17 `send_http_header` + `sub_page_*` pairs collapse into `WRF_PAGE` rows. `/setparam/`, `/callfunction/`,
`/getparam/` keep the trailing slash the GUI and `Web-API_documentation.txt:54-` use.
The auth gate (:1256-1283) uses the route result: a page route without a session gets the login page, any other
non-`WRF_NO_AUTH` route gets 401, `/` gets the login scaffold; this replaces `indexOf("/?page=")` and
`indexOf("HTTP/1.1") > indexOf("/")+2`.

### 6.4 Field extractor and decoders: `web_query.h`, `url_decode`, `hex_digit.h`

```cpp
static inline int mcHexVal(char c);                                                                        // hex_digit.h: 0..15 or -1
enum : uint8_t { URLD_LEGACY = 0, URLD_STRICT = 1, URLD_TRUNC = 2 };                                       // LEGACY = today's url_percent_decode; STRICT = rmparse::decode (reject controls, '+' literal, %22 kept); TRUNC = stop at cap on a UTF-8 boundary
size_t urlDecode(char *buf, size_t len, uint8_t policy);                                                   // in place, NUL at buf[ret]; (size_t)-1 on STRICT reject; url_percent_decode(buf,len) = urlDecode(buf,len,URLD_LEGACY)
bool webQueryFirst(WebSpan query, WebSpan *key, WebSpan *val);                                             // "name=value": key up to the first '=', val = rest (may contain '=' and '&'); false when there is no '=' (D2)
bool webQueryGet(WebSpan query, const char *key, WebSpan *val);                                            // exact key, val up to the next '&'; first match; for sendmessage tocall
bool webQueryTail(WebSpan query, const char *key, WebSpan *val);                                           // exact key, val = everything after "key=" to the end (today's `message` rule, :4882)
size_t webFieldDecode(WebSpan in, char *out, size_t cap, uint8_t policy);                                  // copy + decode into the caller's buffer; ret = length; (size_t)-1 when it does not fit and policy != URLD_TRUNC
```

`webQueryFirst` is the one extractor behind `setparam`, `callfunction` and `getparam`; `webQueryGet`/`webQueryTail` serve
`send_message`; `sub_page_neighbours` reads `x` through `webQueryGet` instead of `indexOf("&x=")` on the whole header.
Caps (stack buffers, nRF52 loop task has a 4 kB stack, `nrf52_flash.cpp:64`): name 32, value 200 (= `message_text[200]`
of `web_setup.cpp:266`, so the silent truncation of D11 becomes a 422), function parameter 64, `tocall` 16, `message`
152 decoded. One buffer pair live at a time, at most 260 bytes; no `String` on the hot path. The existing
`setupStruct` (`web_setup.h`) keeps `String` fields for now (the 66 rungs use them); it is filled from the buffers, so the
churn drops from about 3 kB to two short Strings. Changing `setupStruct` to `const char *` is a later step.
