# RCA CET-AGE-01: stale `{CET}` beacons step the clock backwards (2026-11-08)

BLUF: the receiver has no age or monotonic check at all. The `{CET}` apply path (`src/loop_functions.cpp:2972-3010`) writes the
payload time into the clock as is, whatever its transit age. The 150 s age gate (`CET_MAX_AGE_S`, `src/cet_age.h:16`) exists only on
the TX/relay side and needs a trusted clock, which a `--timesrc cet` or field node by definition does not have. Every observed
backward step is one beacon of the second server source (`OE1XAR-63`) that reached the bench at hop nibble 0 over a path of 4,
26 to 114 s after its payload time; its delta equals minus its age to the second. Analysis only; no source, tool or test changed.

## 2. Why the beacon is old when it arrives

- Stream A (`OE1XAR-33`) reaches the gateway by UDP with age -1..0 s (`gw_rx`, hop 2) and is heard fresh from the gateway.
- Stream B (`OE1XAR-63`) is not delivered to the bench gateway (no `gw_rx` line for it). It arrives over the air with hop nibble 0
  and path count 4, i.e. it has used up its budget on a relay chain. Each relay queues it as prio 3 for 17-32 s per hop
  (`docs/tx-pool-dedup-concept-20261021.md:704-716`), the relay gate allows up to 150 s (`cet_age.h:16`). 26-114 s fits.
- HYPOTHESIS (not proven): B is injected by a gateway on another island, so the bench only sees the tail of the relay chain.
  Decided by: `[CET];rx;src;<call>;age_s;<n>;trusted;1;hop;<h>;path;<p>` on a trusted-clock observer (RAK90, T-Deck-14). The line is
  unconditional (`lora_functions.cpp:2223-2225`, `cet_age.h:201-209`); no debug switch needed. For the hop-by-hop wait use
  `--loradebug` on the relay nodes (`[MC-DBG] RELAY_QUEUED`, `wait=` in the RLY line, `[CET];tx;age_s;..;wait_ms;..`).
- Side finding: the bench gateway itself sent a stale copy of stream A (`[CET];tx;age_s;23;...;wait_ms;23699`, log `:3961`, 23.7 s in
  its own TX queue). Same msg_id as the fresh DK5EN-98 copy, so it dedups where both are heard; where only the gateway
  is heard, the node is behind by 23 s.
- The relay chain does not rewrite the payload, so a relayed copy's age equals total delay since the server stamped it
  (server leg + every queue wait + air time). That is what the receiver would have to know and cannot.

## 3. ESP32 vs nRF52, field case

- Identical code: one `sendDisplayText()` branch for both (see Step "Main loop"). The nRF52 RAK90 log above is the same logic
  that the ESP32 nodes ran.
- With NTP, GPS fix or RTC the branch is skipped (:2980), so the stale beacon cannot touch such a node. The field case is a node
  without all three. Confirmed from the condition; that the T3 S3 field tester has no GPS, no RTC and no WLAN is taken from the
  brief and not checked in the board defines here.
- Such a node cannot apply the 150 s gate (`cetDeviceTrusted()` is false) and it does not relay (D2), so it is also a pure sink
  for whatever A or B copy arrives first.

## 4. Fix options

| Option                                                                                            | Pro                                                                                                                                                                 | Contra                                                                                                                      |
| ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| R1 receiver guard: ignore a step back of more than 5 s within 30 min of the last accepted `{CET}` | transit delay only ever makes a payload older, so the largest payload is the best estimate; works against any producer incl. old firmware; no reach loss; ~15 lines | one wrongly-ahead clock stays wrong for up to 30 min (then recovers); a node that only hears stream B keeps the best B seen |
| R2 accept only hop nibble >= 1                                                                    | trivial; concept 10.8 R3                                                                                                                                            | B is hop 0 here but relayed A copies also drop to 0..1 beyond one relay; nodes without a direct gateway get no time         |
| R3 subtract per-hop delay                                                                         | none robust                                                                                                                                                         | waits are 17-32 s per hop, plus an unknown server and gateway leg; a constant would over- or under-correct                  |
| R4 lower `CET_MAX_AGE_S` to 30 s                                                                  | one line                                                                                                                                                            | kills relayed beacons at the relay gate (waits of 17-32 s per hop), shrinks reach; changes D1 of `campaign-tx-pool.md:23`   |

Recommendation R1, with threshold X = 5 s and window M = 1800 s (three beacon intervals, so recovery from a wrongly-ahead clock is
bounded). After M with no accepted beacon the next one is accepted unconditionally; a first beacon after boot is always accepted.

- Pure decision in `src/cet_age.h` next to `cetFrameStale()` (:138-141):
  `cetStepAllowed(int32_t delta_s, bool have_last, uint32_t since_last_ms)`, false iff `have_last && since_last_ms < 1800000 &&
delta_s < -5`.
- Call site `src/loop_functions.cpp:3002-3006`: parse with `cetParsePayload()`, take `cetNowUtc()` (needs `#define CET_AGE_WITH_CLOCK`
  before the include in `loop_functions.cpp`; the clock part is skipped for UNIT_TEST), `delta_s = payload - now`, keep
  `static uint32_t lastCetOk_ms` (+ flag) set only on a really applied beacon. On skip print `[CET];skip;delta_s;<n>;ms;<ms>`.
  The `Year > 2023` check stays.
- Not covered: a node that only ever hears delayed beacons, and the first beacon after boot or after M of silence; the
  forward correction by the next fresher beacon is then as large as the staleness (CLK-01 A3 is only meaningful in steady
  state). Real fix for that is a transit-age field in the frame (wire change, not proposed).
- Effect on CLK-01: with R1 the bench pattern (stale step every ~600 s, then forward) reduces to one forward step per genuinely
  better beacon, i.e. the clock error stays at the best beacon age and A3 holds in steady state.

## 5. Test that decides it

Suite `test/test_cet_age/test_cet_age.cpp` (env `native_cet_age`, `platformio.ini:1107`; run `pio test -e native_cet_age`, one pio
process). New case `test_step_guard` in the `RUN_TEST` list (:130-136):

- reject -114.5 s, -31 s, -26 s, -22 s, -34 s steps at since_last 60 s (the five measured stale steps);
- accept +25 s forward, -3 s and exactly -5 s (tolerance), accept -114 s when `have_last` is false and when since_last >= 1800 s;
- boundary: since_last 1799999 ms rejects, 1800000 ms accepts.

Before the change it fails to build (`cetStepAllowed` undefined), so the "fails before" is a compile failure; the call-site wiring is
not host-testable (`loop_functions.cpp` is not in the native env). Bench re-check: `--timesrc cet` 2 h on T-Beam 92 and Heltec 1;
expect no negative `delta_ms` beyond -5000 in the `[CLOCK];set` rows while `[CET];skip` lines appear at the former stale times.
