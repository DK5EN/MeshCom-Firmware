## Observed inconsistencies (lines 1-3430)

1. Inverted aliases: `--proz off` is `--volt on` and `--volt off` is `--proz on` (1068, 1084). Asymmetric mask: `proz on` clears with `& 0x7FFE`, which also clears bit 15, while `volt on` sets `0x0001` only.
2. `--bme off` and `--bmp off` share the `--bmx off` body (2328), so both also disable BMP390 (`s3 &= ~0x0010`). The N-28 comment (2339-2346) says only `bmx off` is the collective command and `bme/bmp off` touch only their own chip. Comment and code disagree.
3. Shared bit 0x0010 in node_sset3 is written by `--390 on` (2303), `--390 off` (table 451) and every `bmx/bme/bmp off`. Three commands own one bit.
4. `--setlog on` (table 443) runs `tg_post_setlog_off`, which clears `LogCallsign`. "on" and "off" both clear the callsign, and `--setlog <call>` (1100) sets it. The post name and behaviour do not match "on".
5. `--debug on/off` (sset bit 0x0008, bDEBUG) and `--debug csv/man/en/de` (sset4 0x0001/0x0002, bDEBUGCSV/bDEBUGEN) share the word "debug" for unrelated flags.
6. Numeric and word forms mixed: `--gpsdebug 0/2/<n>` vs `--gpsdebug on/off`. `gpsdebug 2` echoes BLE "--gpsdebug on", and `gpsdebug <n>` echoes "--gpsdebug on" for any value. `--loradebug`, `--wxdebug`, `--bledebug` take only on/off.
7. BLE echo prefix: `-softserdebug off` and `-softserread off` (3136, 3152) use a single dash, all other echoes use `--`.
8. Ordering dependence (all rely on the rung order and the exact-token rule): `kiss` (2666) and `netconsole` (2583) must stay after their longer forms because the bare name also matches `kiss tx on` and `netconsole on`. `setlog ` (1100) and `gpsdebug ` (3081) are prefix-form rungs that would match `setlog on` and `gpsdebug 2`. `via ` (2943) would match `via on`. All are safe only because the table (`toggleApply`) runs first, and `via on` returns from the table block. `--msgid` before `--msg` (1501) is no longer required (exact match), but the comment at 1495 still says it is.
9. `--button gpio` (1728) sets `iButtonPin = ibt` (the OLD pin) before `init_onebutton()`, which uses `iButtonPin` (onebutton_functions.cpp:306-313). A new pin is probably not started live until reboot. Not verified on hardware.
10. `--onewire gpio` (2407) on RAK4630 writes `node_owgpio` via cmdStoreInt, and the `<= 2` rejection comes after. The rejected value stays in RAM and is saved by any later save.
11. `--extudpip` (2805) refusal blanks the stored `node_extern` before returning, without a save. The existing target is lost in RAM until the next settings write or reboot.
12. `--btcode` (3298): a non-number parses to 0, and 0 disables BLE security silently. The comment says it is "only allowed on an already-authenticated connection", but the rung has no such check.
13. Silent value rewrite on non-number input: `--button gpio` and `--analog gpio` keep the old value and still save (sscanf unchecked). `--maxv`, `--postime` (silent clamp), `--gpsdebug <n>`, `--softser baud/rxpin/txpin` and `--utcoff` have no error. Others use cmdArgNotNumber/cmdStore* ("is not a number", "out of range"). Mixed error policy.
14. Missing range validation: `--maxv`, `--utcoff`, `--analog factor/alpha/batt factor`, `--gpsdebug <n>`, `--softser baud/rxpin/txpin`, `--via` (no callsign check), `--setublox`/`--setl76k` (any value that does not start with "on" means OFF, and "setublox foo" disables).
15. Range mismatch: `--button gpio` accepts 0..99; `--analog gpio` accepts 1..98. Both are GPIO pins with the same pattern.
16. `--softser fixtemp` (3251) truncates at `msg_text[22]`, so the value is 4 characters. The comment says 40 and the same pattern at 50 gives about 31 for fixpegel. Likely bug.
17. `--postime` comment says "minimum 3 Minuten" (1040 area) but the code clamps to 5 min (300 s).
18. Password echoes: `--webpwd` (2704) echoes the full command line to BLE, including the cleartext password. `commandAction()` prints `MORE:<...>` (626, 648) and `ONE:<...>` (657) with the full command, including `--passwd <pw>`, to serial when `--setcont on`. `--passwd` itself does not echo.
19. Save gaps: `--settime`, `--setpress`, `--softser fixpegel/fixpegel2/fixtemp`, `--webtimer 0`, `--setretx on/off`, `--viadebug`, `--ackinfo`, `--t5` do not save (some intentionally RAM-only). `--settime` has no persistence at all, so the clock is only set until reboot in the non-RTC path.
20. Reboot policy differs: `--reboot` and `--cleanflash` restart after 2-3 s with no delay for the BLE message. `--bleshort`, `--blelong`, `--gateway srv` (when bGATEWAY), `--setboostedgain on/off` use a 5 s rebootAuto. `--dfu` uses 2 s. The T-Deck skip (`#if !BOARD_T_DECK`) appears on some reboot rungs and not others.
21. Chain breaks (not `else if`): `--gps off` (2053-2082), `--setublox` (3097) and `--setl76k` (3116) start a new `if` chain after the previous `}`. They work because the tokens are exact, but the structure is inconsistent. `--gps off` also does not `return`.
22. Bit reuse on node_sset: `--gps off` (2053) clears 0x0020, the `--track` bit, as a side effect. `--track on/off` (2006, 2032) owns 0x0020 and `--mesh` uses 0x0020 in node_sset2 (inverted). The same bit number on different fields is confusing but correct.
23. Many masks on node_sset also clear bit 0x8000 (`--shortpath off`, `--button off`, `--msg`, `--gps off`, `--bmp on`, `--bme on`, `--bleshort`, `--proz on`, `--display on`, `--bmx off`), for example `& 0x7EFF` and `& 0x7F7F`. Confirm the bit is unused; `--nopmother` uses 0x8000 in node_sset3.
24. Inverted storage on `--mesh` (462-463) and `--nbrsym` (478-479) (on clears the bit) with no marker in the name. Documented in comments only.
25. `--display on` comment (1540) says "set bDisplyOff" for 0x0004, which is bDisplayPos (meshcom_settings.h:93). Copy-paste comment in `--display on/off` (1566).
26. Naming styles: `--setcont/--setinfo/--setretx/--setlog` (set prefix, table), `--setname/--setpress/--setublox/--setl76k` (set prefix, ladder), `--volt/--proz`, `--all/--msg`, `--shortpath`, `--nomsgall`, `--bmx/--bme/--bmp/--390/--680/--811` (chip names), `--softser*` (namespace), `--gpsdebug` vs `--gps`. No single verb pattern.
27. Typo "EXPUDP" in the `--extudp on` refusal (2782).
28. Stale comments: netconsole (2583) "prevent match against --tls" (no such rung); `--msgid` ordering comment (1495-1500) describes a prefix rule removed by D2-10.
29. `--rotate` and `--contrast` silently ignore invalid values (rotate prints only under bBLEDEBUG; contrast clamps 0 to 1 without message).
30. Shared fields are otherwise consistent: `--display on`, `--all` and `--msg` all use s 0x0004 (bDisplayPos). `--gateway pos/nopos` (s2 0x0100) and `--netconsole` (s2 0x1000) do not collide with `--gateway on` (s 0x1000, a different field).
