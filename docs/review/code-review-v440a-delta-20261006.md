## 2. Operator decisions

Settled 2026-10-06:

- **No punishment and no rate limiting until an admin turns the flag on.** With the brute-force flag OFF, only correctness checks may reject a frame: HMAC tag, replay counter (HWM), format, allowlist. Everything else is gated behind the flag: the receiver lockout, the receiver command/sync rate limits, the sender unanswered-budget limit, the sender 10 s cooldown, and the one-shot force.
- The flag can be set from serial `--` and the web GUI settings page. It **cannot** be set over RM.
- **D1 (decided):** RM stays open on both paths, LoRa and the internet/server path (RM-GWRELAY), with no cap when the flag is OFF. The open internet guessing surface (CR-01) is an accepted risk; the flag is the admin's remedy.
- **D2 (decided):** the receiver rate limits (`RM_RATE_MS` 10 s, `RM_SYNC_RATE_MS` 60 s, `remote_cmd.cpp:555-565`) apply only with the flag ON.
- **D3 (decided):** the whole sender policy (unanswered-budget limit, cooldown, one-shot force) applies only with the sender's flag ON. The `static_assert` that couples sender spacing to receiver spacing (`rm_runtime.cpp:21`) stays valid for the flag-ON pair. Known consequence: a flag-OFF sender can push a flag-ON target into its lockout; document this in the `--rmstrictsecurity` help text.

- **Q1 (decided):** strict mode keeps today's per-sender-callsign lockout (3 rejects in 90 s, 5 min); no global lock.
- **Flag name (decided):** serial `--rmstrictsecurity on|off`; settings member `node_rmstrict` (13 chars, inside the 15-char NVS key limit); web label "RM strict security (brute-force protection)".
- **Airtime guards (decided):** the cached-reply spacing and the CR-03 duplicate-reply suppression are not penalties and stay active regardless of the flag.

- **D4 (decided):** the RM page stays on nRF52 (RAK). No `-D` compile-out. FL-01 is limited to shrinking it (gzip/minify measurement, dedup).
- **D5 (decided):** the MTU, Store node and Manual command cards on the settings page become collapsible like every other card.
- **D6 (decided):** `Pin on`/`Pin off` (`web_rm_page.cpp:90`) becomes a single toggle. `setout` is write-only, so the switch starts `indeterminate` and shows the last value sent from this page.

No decisions are open.

Implementation spec:

- **Storage:** a dedicated member `M(int, node_rmstrict, 0)` in `src/meshcom_settings.h`, next to `node_rm` (around line 200), plus a row in `src/config_json.h` (`0..1`, `CFG_NOESC`). **Do not** use a `node_sset4` bit: only 0x4000 is free, 0x8000 is cleared as a side effect by `--setlog off` (`command_functions.cpp:428`), and there is a history of collisions. **Do not** touch `src/nrf52/ble_settings_v1.h` (frozen).
- **Serial:** `--rmstrictsecurity on|off` next to `--remotemgmt` (`command_functions.cpp:4655-4695`); `save_settings()`; print `[RM];strict=on|off`. Add to the `--info` RM line (`:6692-6698`).

- **Not over RM:** do not add it to `RM_ALLOWLIST` (`remote_cmd.cpp:157`). Add a test that asserts `rmstrictsecurity` is rejected as not allowlisted.
- **Plumbing:** `remote_cmd.cpp` is Arduino-free. Pass the flag as a field on `RmState` (or as a parameter), set it from the `rm_runtime.cpp:552` call site, and read it in `reject()`. Do the same for the sender policy.
- **Tests:** every lockout test in `test/test_remote_cmd/test_main.cpp` (lines 637-871, RUN_TESTs 1787-1825) sets the flag ON. Add flag-OFF twins: N wrong tags never lock, a replay is still rejected, a bad tag is still rejected. Update `test/test_rm_policy_rx/test_main.cpp:201` and `test/test_rm_sender_policy/test_main.cpp:282`. Registry tests: `test/test_config_json`, `test/test_command_setters`, `test/golden/settings_schema_lint.py`, `test/test_settings_members`. Use `node_updchan` as the template.
- With the flag OFF the RX path is: parse, allowlist, HMAC, HWM, execute. No reject is counted as a penalty, nothing waits. Tests: N wrong tags from one and from rotating callsigns never lock; back-to-back valid commands 1 s apart are all executed; a replay and a bad tag are still rejected.
