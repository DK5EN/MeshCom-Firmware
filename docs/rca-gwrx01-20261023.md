# RCA GWRX-01: gateway transmits a server frame after hearing it on air (2026-10-23)

BLUF: the hypothesis holds. No scan in `OnRxDone` can release a pending `udp_rx` slot (status DONE, length > 0, `ringSource == 'g'`), on fork-dev and on upstream/dev, ESP32 and nRF52 alike. The 2026-10-13 capture ran a build without QRT Finding 1, and Finding 1 would not have helped anyway (READY slots only). The "wasted airtime" premise is only partly true: in 28 of 34 frames a neighbour relayed the gateway's own copy, so the transmission reached nodes that the earlier copy had not. Measured cost is small (26.6 s per 8.8 h for all 34, 4.3 s for the 6 clearly redundant ones). Recommended fix: option (b), NBR-gated cancel, first in count mode. Option (a) would drop useful copies.

Analysis only. No source, tool or test file was changed.

## 1. Hypothesis on fork-dev HEAD

CONFIRMED. All line numbers are fork-dev HEAD (53681dd1).

- Enqueue: ESP32 `src/esp32/udp_frame_esp32.cpp:579` `addTxRingEntry(convBuffer, size, 0xFF, "udp_rx", 0)`, nRF52 `src/nrf52/udp_frame_nrf52.cpp:564` with `RING_STATUS_DONE`. Both are 0xFF (`configuration_global.h:427`). `insertOwnTx(msg_id)` runs just before (`:577` / `:562`), so the id is already in `own_msg_id[]`.
- Slot identity: `addTxRingEntryCore` stores `ringSource[w] = setlogRingSourceCode(source)` (`txring_functions.cpp:730`); `"udp_rx"` maps to `'g'` (`setlog_lines.h:176-189`). `ringKind` stays `RING_KIND_OTHER` (default, `txring_functions.cpp:736`).
- Pending vs sent: `getNextTxSlot` (`txring_functions.cpp:198-253`) selects slots with `ringBuffer[pos][0] > 0` and status READY or DONE. `doTX` copies the frame out and writes `ringBuffer[txSlot][0] = 0` (`lora_functions.cpp:2953`, "Mark as consumed"); rollback paths restore the length (`:3034`, `:3049`, `:3079`, `:3101`, `:3148`, `:3185`); drop paths leave it 0 (`:3208`). So a slot is "untransmitted udp_rx" iff `len > 0 && status == DONE && ringSource == 'g'`, and a sent one has `len == 0`. The id sits at `ringBuffer[i][3..6]`.
- Priority: a text slot with status DONE is classified as relay priority (`getMessagePriority`, `txring_functions.cpp:131` returns `MSG_PRIO_NORMAL`). That is why every `src=g` line in the capture shows `prio=3`, and why the slot waits (average `wait=7784 ms`, max 27245 ms over all 89 `src=g` lines).
- The three scans, each checked against a pending udp_rx slot:
  - ACK/RX-OK scan, `lora_functions.cpp:1026`: condition `status != DONE && status != READY` excludes it.
  - READY release (QRT Finding 1), `:1035-1068`: `status == READY` and `pnFrameIsReleasableGroupText`; a udp_rx slot is DONE, so it never enters.
  - NBR relay cancel, `:1281-1400`: outer gate `bNBRRELAY` plus a path with `,` and last hop not self (`:1281-1284`); inner filter `(ringKind & 0x7F) == RING_KIND_RELAY && status == DONE && same id` (`:1313-1316`); the actual free needs `bNBRCANCEL` (`:1386`). A udp_rx slot has kind OTHER, so it is skipped. The orchestrator's brief names only `bNBRCANCEL`; the outer gate is `bNBRRELAY`.
- Heard-before-GWI is already handled: if the id is in the dedup ring when the server frame arrives, `bUdpMsgIsNew` is false and nothing is enqueued (`udp_frame_esp32.cpp:220`, `:280`). The defect window is only "heard between enqueue and TX".
- The `heardIcheck >= 0` branch (`lora_functions.cpp:1656`) does see the echo and sets `own_msg_id[..][4] = 0x01` (HEARD, `:1693-1696`, text frames only, and only while status is 0x00 or `bAckInfo`). It never touches the ring.

## 4. Who sent the heard copies

CONFIRMED, all 34 frames (39 `DUP:d` lines) classified, not a sample. Method: `awk` on the capture, per GWI id the first `DUP:d` RX line before the `TX ... src=g` line (scripts in the session scratchpad; no log was read whole).

- 34 distinct ids / 39 lines (5 ids heard twice before TX), of 89 GWI/`src=g` pairs overall (38 % of server frames).
- First-heard copy, path before `>`: `OE1XAR-33,DF2SI-12` for 32 frames, `OE1XAR-33,DL2JA-2` for 1 (`x6ACC63DA`, line 101467), `OE1XAR-33,DL2JA-2,DL2UD-1` for 1 (`x6ACC63C8`, line 63380, hop H01).
- The 33 direct copies carry the same hop value as our GWI line (22 x H02, 11 x H04). A relay decrements it: later copies in the same capture show `H01` (example `x6ACC63A6`: DF2SI-12 H02 at line 1171, DL2JA-1 relay H01 at 1218). So these are not relays: another node injected the same server frame, i.e. a second gateway in range (DF2SI-12, DL2JA-2). The log does not prove those two are gateways (UNVERIFIED by identity); the unchanged hop value and the identical timing pattern are the evidence.
- Class: 23 of 34 are the server time beacon `{CET}` from `OE1XAR-33` (60 B), 11 are group texts (H04, 51 to 153 B).
- Timing: GWI to first echo 0.9 to 9.1 s (median 3.0 s); first echo to our TX 3.9 to 24.2 s (median 4.9 s); nearest echo to TX 3.9 to 15.5 s. The R0 doc quotes 3.9 to 10.7 s; the 10.7 upper bound is not reproduced (UNVERIFIED which subset it used).
- Signal: first copies at RSSI -127 to -106 dBm (median -126, 32 of 34 at -123 or weaker). The other gateway is at the edge of the gateway's range.
- Value of our later copy, per id (path containing `DK5EN-98,` = a neighbour relayed our copy): 28 of 34 had at least one such relay (mostly `DL2UD-1`, `DB0ED-99`). Those neighbours had not heard the earlier copy, otherwise dedup would have stopped them. 6 of 34 had none: `x3DF6E07E`, `x6ACC63AE`, `x6ACC63BF`, `x6ACC63C8`, `x6ACC63D6`, `x6ACC63DA`. A relay-free outcome is not proof of uselessness (leaf listeners do not relay): these 6 are the upper bound of redundant sends.

## 6. nRF52 parity

CONFIRMED by code, UNVERIFIED on hardware.

- Enqueue identical in effect: `udp_frame_nrf52.cpp:564` `RING_STATUS_DONE`, label `"udp_rx"`, after `insertOwnTx` (`:561`); the three `OnRxDone` scans are shared code with no `#if` that changes the DONE exclusion. The nRF52 server path needs the W5100S Ethernet link (RAK4631 gateway, `:544-551`).
- Differences that matter for a fix: on nRF52 `OnRxDone` runs in the LORA task while `doTX` runs in the loop task (`nrf52_main.cpp:1728`), so a new ring write from `OnRxDone` needs the `taskENTER_CRITICAL` pattern the existing scans use (`lora_functions.cpp:1046-1061`, `:1375-1411`); on ESP32 both `OnRxDone` (`esp32_main.cpp:5468`) and `doTX` (`:3908`) are called from `esp32loop()` (`:3129`), so no lock is needed there (call-site argument, task identity not otherwise verified).
- No nRF52 gateway capture with GWI lines was analysed.

## 7. Fix options

Common facts: the `heardIcheck >= 0` branch and the RX-OK scan both see the echo; a pending slot is found by `ringSource == 'g' && len > 0 && status == DONE && id match`. Any new ring write on RAK4630 must re-check the slot inside one `taskENTER_CRITICAL()` section and free it with the same three writes the READY release uses (`status = DONE`, `len = 0`, `retryCount = 0`, `:1054-1056`); no `printfdeb` or malloc inside the lock. The window between `getNextTxSlot` and the length reset in `doTX` is unlocked (the NBR cancel comment accepts it, `lora_functions.cpp:1390-1396`).

### (a) Cancel on any overhear of the id

- Site: a third branch in the RX-OK scan (`lora_functions.cpp:1026-1068`): `else if(len > 0 && status == DONE && ringSource[i] == 'g' && id match)`, release under the RAK lock. Alternative site without any RX-side ring write: in `doTX`, before consuming a `'g'` slot, skip it if `own_msg_id[checkOwnTx(id)][4] != 0x00` (HEARD, set by `:1696`); this runs in the loop task, so no new cross-task window. It covers text only.
- Risk: drops copies that carry the frame to nodes the heard transmitter does not reach. Evidence section 4: the earlier copy was heard at -126 dBm median, and in 28 of 34 frames a neighbour relayed only our later copy. Applying (a) would likely remove coverage in most of the 39 events to save 4.3 s of redundant airtime. Also any foreign node can cancel a gateway's injection by replaying the id first. Rejected unless the operator prefers airtime over reach.
- Test: see the generic seam below.

### (b) Cancel only when the NBR matrix says the heard copy covers the gateway's dependents (recommended)

- Site 1, enqueue: pass kind/need/alone at both `udp_rx` calls (`udp_frame_esp32.cpp:579`, `udp_frame_nrf52.cpp:564`) as `rx_relay` does (`lora_functions.cpp:2554`): `RING_KIND_RELAY` with `nbrRelayNeed()` output when `bNBRRELAY` and `known`, else `RING_KIND_OTHER` (no knowledge: send as today). `nbrRelayNeed` already excludes `NBR_FLAG_GW` rows (`nbr_matrix.h:762-765`: gateways get the frame from the server) and gives an `alone` veto for sole providers. Whether `nbrRelayNeed(matrix, <server source call>, ...)` returns `known == true` for a path whose only token is a call that is not a matrix row is UNVERIFIED; if not, a thin variant computing `(Direkt | HoertMich) & ~GW-rows` is needed (`nbr_matrix.h:757-767`).
- Site 2, cancel: the existing NBR scan (`lora_functions.cpp:1281-1400`) then handles the slot unchanged: it needs a heard copy with a `,` in the path and last hop not self, subtracts `nbrCopyMask(relayer)` from `ringNeed`, frees the slot when `need` is empty and `alone` is empty, under the RAK lock. Count mode (`--nbrrelay count`) only logs `CANCEL?` and counts `stat_nbr_cancel_possible` (`:1407`), so the effect can be measured on DK5EN-98 before cancel is enabled.
- Risks: (1) non-text server frames (position 0x21, HEY) with kind RELAY pick up the Case-B CSMA hold (`txring_functions.cpp:291-310`, `lora_functions.cpp:3942`) that text is excluded from; restrict the kind to `payload == ':'` or accept the hold consciously. (2) CANCEL/REFUSE log lines and `stat_nbr_*` counters mix relay and server slots; add a marker or accept. (3) Gain is small (about 4.3 s per 8.8 h on this capture); the matrix may veto most of the 6 redundant cases because `DF2SI-12` is weakly heard and `DL2UD-1`/`DB0ED-99` relayed only our copy. That is the intended behaviour.
- Test seam: the relay-cancel body is inline in `OnRxDone` and not host-testable. Extract the per-slot step (id match, need subtraction, release under lock) into `txring_functions.cpp` as a function taking the received id, the cover mask and the cancel flag, and keep `OnRxDone` as a thin caller. The existing suite `test/test_txring/test_txring.cpp` (env `native_aprs`, `platformio.ini:332`) already builds `txring_functions.cpp` natively and tests `ringKind/need/alone` (`test_stufe2_kind_need_alone_werden_gesetzt`).

### (c) Others

- (c1) TX-time HEARD guard, see (a) alternative site: smallest diff, loop-task only, text only, same coverage trade-off as (a).
- (c2) Gate (a) on signal: cancel only if the heard copy is stronger than a threshold. In this capture 32 of 34 first copies are at -123 dBm or weaker, so a threshold would almost never fire; useless for these events, noted for completeness.
- (c3) Shorter dwell: server frames wait 5.7 to 27.2 s (`wait=`) because DONE text classifies as `MSG_PRIO_NORMAL`. A higher priority for `'g'` text would shrink the window in which another gateway's copy overtakes ours, but raises contention for every other class. Not recommended without a bench.

### Recommendation and regression test

Recommend (b), count mode first: ship the enqueue change with `--nbrrelay count` semantics, read `stat_nbr_cancel_possible` on DK5EN-98 for a night, then enable cancel. Do not implement (a).

Regression test, `test/test_txring/test_txring.cpp` (native, `pio test -e native_aprs -f test_txring` through the lock wrapper), named `test_gwrx01_*`, against the extracted per-slot helper (call it `txringServerCopyHeard(rx_id4, cover, allow_cancel)`):

1. `test_gwrx01_udp_rx_slot_released_when_heard_copy_covers_need`: `addTxRingEntry(frame, len, 0xFF, "udp_rx", 0, false, RING_KIND_RELAY, &need{rowA}, &alone{})`; call the helper with `cover = {rowA}`; assert `ringBuffer[slot][0] == 0` and `getNextTxSlot() == -1`. On today's code the slot stays selectable (`getNextTxSlot() == slot`), so a characterization variant of the same test with the OnRxDone-equivalent scans fails the assertion; the helper itself does not exist yet, so before the seam lands the test is red at link time.
2. Same setup, `cover` does not include `rowA`: slot survives.
3. `alone` non-empty (sole provider): slot survives even with full cover.
4. Unknown relayer (empty cover): slot survives.
5. Already sent slot (`len == 0`, as left by `doTX`): helper returns "no slot", no write.
6. Different id, and a DONE slot with `ringSource 'o'` or `'r'` and the same id: untouched.
7. `allow_cancel == false` (count mode): slot survives, `stat_nbr_cancel_possible` increments once (the COUNTED bit).

Not hostable natively: the RAK4630 lock (`BOARD_RAK4630` is not defined in native envs) and the two udp_frame call sites; those need a bench pass on DK5EN-1 (`--injectraw` plus a server-style frame) and a code review of the lock placement. Run `tools/regression.sh --stage 1,2`.

## Other findings (not fixed)

- `src/lora_functions.cpp:1043-1045` states that `getNextTxSlot()` runs under `taskENTER_CRITICAL()` in `doTX`; `doTX` calls it unlocked (`:2867`; no critical section between `:2860` and `:3016` other than `vTaskSuspendAll` around sends). The accepted window is documented at `:1390-1396`. Comment is misleading.
- `tools/loganalyse.sh:2706-2723`: "SF11/BW250 ~3 ms/byte" is too low; at SF11 / BW250 / CR 4/6 the payload alone is about 9 ms/byte plus 0.3 s fixed preamble/header (60 B = 0.707 s). The EST_AIRTIME columns understate by 3 to 5 times (UNVERIFIED which profile the fleet logs were recorded with).
- `docs/rca-dup-r0-findings-20261013.md` calls the 39 lines "39 cases"; they are 34 frames (5 heard twice). Its 10.7 s upper bound is not reproduced (section 4).
- Gateways that sit within each other's range inject the same server frame independently (23 of 34 were the 10-minute `{CET}` beacon); each added gateway adds one copy per beacon. This is a design property of the injection path, not a defect of one build.
