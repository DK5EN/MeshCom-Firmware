## Platform

The unit is compiled as the ESP32 build of the request path (`#define ESP32` after the real headers): the AU
gate (`fwWebAdmit`), `/austatus` and `/mcau.js` are in. `ENABLE_MSGSTORE` and `OLED_SHOT_WEB` are set in the
env, so `/?page=mailbox`, `mboxpurge`, `mboxdeliver` and `/screen.oled` are routed. Not in: the T-Deck
`INSTRUMENT` branches (`/screen.rgb565`, `tdecktheme` ... in `setparam`).

## Wiring the live path (next step)

`../test_web_diff.cpp` holds `kEntries` (entry-point table) and `kWhitelist`. A live entry needs:

1. a natively compilable TU with `void work_webpage(void)` (or its refactored replacement) that reads the
   global `web_client` of `../rig/web_rig.h` and uses the shared recorders of `../rig/web_stubs.cpp`;
2. `#include "../stubs/web_handler_stubs.h"` inside its own namespace, with `WEB_RIG_RM_READ`,
   `WEB_RIG_READ_BODY`, `WEB_RIG_CFG_ALLOC/FREE/BUF` bound to its body readers (see the MID block of `extract.sh`);
3. its sources in `build_src_filter` (or the suite directory) of `[env:native_web_diff]`.

The golden check and the first-entry-vs-live check then run for it. Intended deltas (B1-B10) go into
`kWhitelist`, keyed by corpus name, with the defect id as reason.
